PLIK: Attributes
================================================================================

Attributes

Attributes

Attributes are a feature of the API which let a VBA 
 Macro (or DLL or EXE) attach data to a Path object. (Geometry or tool 
 path.) (Also Element, MillTool, Drawing and WorkPlane) Each attribute 
 may be an integer or floating point number, or a string. Each attribute 
 may be read and written using the API, and can be read in the Post Processor. 
 They are saved with the AlphaCAM drawing eg in the .AMD file.

Each attribute is identified by a string. Because the 
 attributes are saved in the drawing file and a user may have more than 
 one add-in using attributes, we need to have a way of choosing the string 
 indentifier so that it is unique. The way we have used is this:

The string should be made up as follows: (no quotes 
 or spaces)

 "Company Name" "Country Code" 
 "Script Writer Initials" "Project" "Identifier"

"Company Name" and "Country Code" 
 refer to the company and country of the script writer. "Identifier" 
 is whatever the script writer wants to refer to it as within that project.

For example, the Nesting in AlphaCAM uses attributes 
 to store data about the nesting. A typical attribute name is:

 "LicomUKsabj_nest_path_file"

ie "Licom" "UK" "Stephen A.B. 
 Jones" "Nest" "path_file".

The country code should be as in Web addresses, (USA 
 should use USA) eg UK = United Kingdom, DE = Germany, IT = Italy, FR = 
 France, CH = Switzerland, JP = Japan, TW = Taiwan etc.

If each script writer uses his company name, country 
 and initials we should avoid conflicts. Each writer just has to worry 
 about the remainder of the name. Each of these strings is stored just 
 once in memory and in the file, so do not worry about a long string wasting 
 memory.

Due to international considerations, the attribute names 
 are CASE-SENSITIVE. They should be declared only once. VBA programmers 
 should use Const, C++ programmers 
 should use #define, Delphi programmers 
 should use const.

The Attribute is set and returned as a Variant. VBA 
 will automatically convert between a Variant and a string or number.

For an example of attaching attributes to geometries 
 see here.

Attributes can also be attached to a MillData (or TurnData 
 or WireData) object. The attributes will then be copied to the resulting 
 tool paths when eg the RoughFinish method is used.

Attributes are stored as Variants. A Variant is a variable 
 stored as a number giving its type and another variable storing the data. 
 The type is determined by the type of the variable or expression used 
 to set the attribute. For example:

 P.Attribute(ATTR1) = "ABC"

will store a string,

 P.Attribute(ATTR1) = 10.5

will store a floating point (double precision) value.

 P.Attribute(ATTR1) = 10

will store an Integer value.

It is recommended to set the type using a variable of 
 the required type. For example:

 Dim X As Double

 X = 10

 P.Attribute(ATTR1) = X

will store a floating point (double precision) value.

The type is important if the data is to be used in the 
 Post Processor. Also, 
 it is easier to read an attribute if it always has the same type. (Particularly 
 in languages other than VBA.)

PLIK: Collections

Collections
 
 

 Collections

 A Collection is an object that is a list of objects. VBA provides a general Collection object which can be used to hold any kind of object, see the VBA help file. AlphaCAM provides Collection objects for many of the AlphaCAM objects. These are usually used to give access to the objects. In AlphaCAM (and in other VBA hosts eg Word) a Collection for a particular type of object has the same name as the object, with 's' added on the end. For example, a Paths object is a Collection of Path objects.

 Collections give a consistent way of accessing a list of objects. The number of objects in a Collection is given by the Count property. An object can be accessed using its position in the list, 1 to Count, eg: (Where Drw is a Drawing object)

 Dim Geos As Paths

 Set Geos = Drw.Geometries

 Dim Geo As Path

 Set Geo = Geos(1) ' gives the first geometry

 Set Geo = Geos(5) ' gives geometry number 5

 Or:

 Dim Geo As Path

 Set Geo = Drw.Geometries(5) ' gives geometry number 5

 If an object has a name, it can also be accessed by name eg:

 Dim Lyr as Layer

 Set Lyr = Drw.Layers("HOLES")

 The above examples actually use the Item method of the Collection. This is the default member so in VBA / VB, Geos(5) is equivalent to Geos.Item(5). In other languages you have to specify Item.

 To loop over all the objects in the Collection:

 Dim Geo As Path

 For Each Geo In Drw.Geometries

 ' Do something with Geo 

 Next Geo

 For other languages see here.

 The Paths Collection has a number of methods which let you do something to all the paths in it. See Paths.

 See Drawing.UserSelectMultiGeosCollection for examples using the Paths Collection.

 The Collections available in AlphaCAM are:

 Elements

 Layers

 Materials

 Operations

 Paths

 SubOperations

 WorkPlanes

 The Collection object is obtained from the containing object. For example, the Collection of geometries in a layer is given by: (Where Lyr is a Layer object.)

 Lyr.Geometries

 Using Collections in Delphi and C++

PLIK: ExampleusingAttributes
================================================================================

Example using Attributes
 
 

 Example using Attributes

 The first Sub draws the characters A to E and attaches an attribute to each geometry making up each character. The attribute is a string containing the character.

 The second Sub asks the user to select a geometry and gets the attribute. If the attribute is not there an empty variant will be returned, so this is tested for. If it is there the string is displayed. For example, clicking on one of the geometries making up the character 'B' displays 'B' in a message box.

 For other languages see here.

 Const ATTR1 As String = "LicomUKdmbManualExampleTest1"

 Public Sub AttributeExample1()

 Dim Drw As Drawing 

 Set Drw = App.ActiveDrawing 

 Dim PS As Paths 

 Dim P1 As Path 

  

 Dim X As Double 

 Dim CH As Integer 

 X = 0 

 For CH = Asc("A") To Asc("E") 

 Set PS = Drw.CreateText(Chr(CH), X, 0, 10) 

 X = X + 20 

 For Each P1 In PS 

 P1.Attribute(ATTR1) = Chr(CH) 

 Next P1 

 Next CH 

 End Sub

 Public Sub AttributeExample2()

 Dim Drw As Drawing 

 Set Drw = App.ActiveDrawing 

 Dim P1 As Path 

 Do 

 Set P1 = Drw.UserSelectOneGeo("Select a Geometry") 

 If P1 Is Nothing Then 

 Exit Do 

 End If 

  

 Dim V As Variant 

 V = P1.Attribute(ATTR1) 

 ' Test to see if the attribute has not been set 

 If VarType(V) <> vbEmpty Then 

 MsgBox V 

 End If 

 Loop 

 End Sub

PLIK: Frame_AddButton
================================================================================

Frame.AddButton
 
 

 Frame.AddButton

 Add a button to a button bar.

 Syntax

 frame.AddButton (BarID, BmpFileName, CommandID)

 AcamButtonBar BarID ID of bar

 String BmpFileName File name of button image

 Long CommandID ID of command that button will run

 Remarks

 BarID can be the ID of one of the existing button bars (see AcamButtonBar in the VBA Object Browser), or it can be the ID returned by a call to Frame.CreateButtonBar, which creates a new button bar.

 BmpFileName is the name of a .BMP file. (The file name only, NOT the complete path name.) It should be in the same directory as the add-in. It should be a 16-colour bitmap, width = 16, height = 15. In the API folder on the AlphaCAM CD is Blank.bmp which can be used as a starter.

 CommandID is the ID of the command that the button will run. It will usually be the value of Frame.LastMenuCommandID after a call to one of the AddMenuItem (2, 3 or 4) methods. It can also be the ID of an AlphaCAM command, see AcamCommand in the VBA Object Browser.

 See AddMenuItem2 for an example.

Frame.AddMenuItem2
 
 

 Frame.AddMenuItem2

 Add an item to a menu. This method will add the item to a specified menu. See AddMenuItem3 if a "pop-out-the-side" menu is required.

 Syntax

 First section of Machine menu.

 Second section of Machine menu.

 Edit section of Machine menu.

 
 This routine may only be used in the Events module of a VBA Macro or a DLL.

 The example will add a menu item called Circles to the end of the Geometry menu. The function Circles (in the Events module in the same VBA project, or in the same DLL) will be called when the menu item is picked. An ampersand (&) in the menu text gives an underline (_) in the displayed menu text for keyboard selection.

 It also adds a button to the CAD Geometry button bar.

 It also adds a menu item called Name to a new menu called Extras, which calls the function MyName.

  ' In Events module in a VBA project in Licomdir\VBMacros\StartUp

  Function InitAlphacamAddIn (AcamVersion As long) As Integer

   Dim frm As Frame

   Set frm = App.Frame

   frm.AddMenuItem2 "&Circles", "Circles", acamMenuGEO, ""

   frm.AddButton acamButtonBarCAD_GEOMETRY, "Circles.bmp", frm.LastMenuCommandID

   frm.AddMenuItem2 "&Name", "MyName", acamMenuNEW, "E&xtras"

   InitAlphacamAddIn = 0

  End Function

  

  Function Circles()

   MsgBox "Circles"

  End Function

  Function MyName()

   MsgBox "Name"

  End Function

 Note that Circles and MyName are Functions, not Subs, because if they are Subs they will appear in the Macros dialog box reached from the Macros command in the VBA Macros menu, which is not wanted if they are on a menu.

 If a function with the same name as the function, with "OnUpdate" in front, is found in the same module as the function, it will be used to enable or disable the menu item, and/or to add a check mark in front of the menu item. It should return one of the following values:

 0 Menu item is disabled and unchecked

 1 Menu item is enabled and unchecked

 2 Menu item is disabled and checked

 3 Menu item is enabled and checked

 If there is no update function the default is 1.

 For example, if in the example above there is the function below:

  Function OnUpdateCircles()

   If App.ActiveDrawing.GetGeoCount > 0 Then

    OnUpdateCircles = 1

   Else

    OnUpdateCircles = 0

   End If

  End Function

 the menu item will be disabled if there are no geometries in the drawing.

PLIK: Frame_AddMenuItem4

Frame.AddMenuItem4
 
 

 Frame.AddMenuItem4

 Add an item to a menu, at any location.

 Syntax

 frame.AddMenuItem4 (ItemName, Function, Location, After, PopupName)

 String  ItemName Name in menu.

 String  Function  Name of function.

 AcamCommand Location  ID of command to add menu next to.

PLIK: Frame_ReadTextFile
================================================================================

Frame.ReadTextFile
 
 

 Frame.ReadTextFile

 Read and decrypt text from AlphaCAM text file or other text file.

 Syntax

 frame.ReadTextFile (FileName, DollarNumber, Index)

 String FileName Name of text file (.txt or .ctx extension), no path

 long DollarNumber $ number to read

 short Index  Line number, 1 = first line after $, 2 = second etc.

 [Return] String  Returned string.

 Remarks

 This is mainly for Licom companies and distributors who want to write an add-in which can be easily translated to other languages. The text file must have the same format as engacam.txt. For example, the text file addin1.txt might contain the following:

 Text for example addin (ADDIN1.DLL)

 $10

 Select Tool

 Tool Library

 Then the statement

 S$ = frame.ReadTextFile("ADDIN1.TXT", 10, 1) 

 will put the string "Select Tool" into S$

 The .txt file should be in the same directory as the DLL or VBA Project that will use it. The file does not have to be encrypted with maketext.exe, AlphaCAM will automatically detect whether it is encrypted or not and read it.

 The statement

 S$ = frame.ReadTextFile("acam.ctx", 2350, 1)

 will put the string "Clear Memory" into S$.

 Note that the numbers in the acam.ctx and aedit.ctx are not guaranteed to stay the same forever, although every effort will be made to keep them compatible.

Frame.RegisterImportFunction
 
 

 Frame.RegisterImportFunction

 Register a function in this add-in which can import a file of a specified type.

 Syntax

PLIK: Frame_RegisterImportFunction2
================================================================================

Frame.RegisterImportFunction2
 
 

 Frame.RegisterImportFunction2

 Register a function in this add-in which can import a file of a specified type.

 As RegisterImportFunction but with CheckFunction to check a file to see if it is the required type.

 This method should be called if a file extension could be used for more than one type.

 This method will work with add-in DLLs only, not VBA projects.

 Syntax

  Frame.RegisterImportFunction2 (FileTypeName, FileExtensions, ImportFunction, CheckFunction)

 String FileTypeName A name for the file type

 String FileExtensions The extensions of this type of file separated by ;

 String ImportFunction  The name of the function which will import the file

 String CheckFunction  The name of the function which will check the file

 Remarks

 CheckFunction will be passed App and file name, should return non-zero if it can be handled.

 When the API method Application.OpenExternalFile is called AlphaCAM
 will look through the list of registered import handlers to see if any can import a file with the extension.
 For each handler the CheckFunction will be called with the name of the file. The function should examine the file to see if it can handle it, and return non-zero if so.
 If a CheckFunction returns non-zero the ImportFunction will be called and should import the file.
 The same process happens when a file of unknown type is "dropped" on to AlphaCAM from Explorer.

 Example (C++)

 In InitAlphacamAddIn:

 frame->RegisterImportFunction2("Parasolid", ".x_t;.x_b", "PSInputFile", "PSCheckFile");

 In the same DLL:

  ACAMAPIFUN(void) PSInputFile(VARIANT Acam, const char *FileName, VARIANT CadSettings)

  // Read the file into AlphaCAM

  ACAMAPIFUN(int) PSCheckFile(VARIANT Acam, const char *FileName)

  // Return non-zero if the file can be handled by PSInputFile

 CadSettings is an object of type CadInputSettings, which contains properties which may be used to control the import eg BreakTol.

 See Application.OpenExternalFile

 Using Attributes in Delphi and C++

 The equivalent code in Delphi to apply attributes is as follows:

 Const ATTR1 = 'LicomUKdmbManualExampleTest1';

 procedure TForm1.Button1Click(Sender: TObject);

 var

 acam: IAlphaCamApp; 

 Drw: IDrawing; 

 PS: IPaths; 

 P1: IPath; 

 X: Double; 

 I, CH: Integer; 

 begin

 acam := CreateOleObject ('am5axaps.application') as IAlphaCamApp; 

 Drw := acam.ActiveDrawing; 

 X := 0.5; 

 For CH := 65 To 69 do 

 begin 

 PS := Drw.CreateText(Chr(CH), X, 0, 10); 

 For I := 1 to PS.Count do 

 begin 

 P1 := PS.Item(I); 

 P1.Attribute[ATTR1] := Chr(CH); 

 end; 

 X := X + 20; 

 end; 

 end;

 Code to read the attributes in Delphi is as follows:

 procedure TForm1.Button2Click(Sender: TObject);

 var

 acam: IAlphaCamApp; 

 Drw: IDrawing; 

 P1: IPath; 

 Attr: OleVariant;

 acam := CreateOleObject ('am5axaps.application') as IAlphaCamApp; 

 Drw := acam.ActiveDrawing; 

 acam.Visible := true;
