PLIK: Application.SetProcessAffinityMask
================================================================================

Application.SetProcessAffinityMask

Application.SetProcessAffinityMask

Set which processor should be used, eg SetProcessAffinityMask(1) 
 to use just the first one.

Syntax

App.SetProcessAffinityMask (ProcessAffinityMask)

long  ProcessAffinityMask The affinity mask 
 for the threads of the process

Remarks

Some legacy programs have problems running on multi-core 
 machines when communicating with Alphacam using COM. Restricting Alphacam 
 to run on only the first cpu can help.

(Only use this call if you know what you are doing, 
 and have read the Microsoft documentation on this function!)

PLIK: Application_OpenExternalFile
================================================================================

Application.OpenExternalFile
 
 

 Application.OpenExternalFile

 Open a file using an import function in an Add-In.

 Syntax

 App.OpenExternalFile (Name, Type, Clear)

 String  Name  Full path name of file to open

 String Type  String giving type of file, may be empty ("")

 Boolean Clear  True to clear memory before reading file

 Remarks

 For example, if the "Parasolid Input" Add-In is loaded (Utils | Add-Ins | Parasolid Input), the following line will read a Parasolid file:

 App.OpenExternalFile "C:\Cadfiles\Part.x_t", "Parasolid", True

 If the Type is empty the extension will be used to determine the import function to use. If the Type is not empty it will be used to find the import function, so any extension can be used.

 See Frame.RegisterImportFunction

PLIK: Application_OpenTempDxfFile
================================================================================

Application.OpenTempDxfFile
 
 

 Application.OpenTempDxfFile

 Open DXF or DWG file into a temporary drawing, which will not be displayed.

 Syntax

 App.OpenTempDxfFile (Name)

 String  Name Full path name of file to open

 [Return] Drawing  Drawing object representing the drawing.

 Remarks

 This can be used to open a drawing that is not to be displayed, and to copy geometries to the main drawing.

 The example opens a drawing and copies circles from it to the main drawing.

 Public Sub TestOpenTempDxf()

 Dim Drw1 As Drawing 

 Dim Drw2 As Drawing 

  

 Set Drw1 = App.ActiveDrawing 

  

 Set Drw2 = App.OpenTempDxfFile("G:\cadfiles\dxftut.dxf") 

  

 Dim P As Path, P2 As Path 

 For Each P In Drw2.Geometries 

 Dim CP As CircleProperties 

 Set CP = P.GetCircleProperties 

 If Not (CP Is Nothing) Then 

 ' Copy circle to main drawing 

 Set P2 = P.CopyTemporary 

 P2.StoreTemporary 

 End If 

 Next P 

 Drw1.ZoomAll 

 End Sub

PLIK: Dimension_CreateAligned
================================================================================

Dimension.CreateAligned
 
 

 Dimension.CreateAligned

 Create an aligned dimension for two points.

 Syntax

 dim.CreateAligned (X1, Y1, X2, Y2, XPosition, YPosition, XControl, YControl)

 double X1 X coordinate of first point

 double Y1 Y coordinate of first point

 double X2 X coordinate of second point

 double Y2 Y coordinate of second point

 double XPosition X coordinate of dimension position

 double YPosition Y coordinate of dimension position

 double XControl X coordinate of control point

 double YControl Y coordinate of control point

 [Return] Paths  Returned Paths object

 Remarks

 The control point is used if the dimension position is to be outside the leader lines and the text is not aligned. The line parallel to the line between the two points will go through the control point, which should be between the leader lines. If the dimension position is between the leader lines the control point can be given any value eg (0, 0)

 The example will draw a line and dimension it:

 Public Sub Aligned2Points()

 With App.ActiveDrawing 

 .Create2DLine 50, 20, 200, 70 

 .Font = "AStencil" 

 With .Dimension 

 .TextPosition = acamDimCENTER 

 .TextAlignment = acamDimHORIZONTAL 

 .TextHeight = 6 

 .ArrowLength = 4 

 .CreateAligned 50, 20, 200, 70, 300, 110, 150, 75 

 End With 

 .ZoomAll 

 End With 

 End Sub

PLIK: ErrorHandling
================================================================================

Error Handling
 
 

 Error Handling

 Some AlphaCAM API methods will "Raise an Error" if they are unable to do the required action. "Raise an Error" means that the macro will stop and VBA will display a dialog box describing the error. (Other languages handle errors differently, see their documentation). For example, if the Application.SelectTool method is called with an invalid tool name, the dialog box will display the text "Error selecting tool". The user then has the option of ending the macro or debugging the code! This is reasonable while you are developing the macro. However, if the macro is to be distributed and used by other people, you should try to avoid these errors. You can trap the error with the On Error statement. The following routine shows how it could be handled. The statement On Error Resume Next suppresses the error dialog box for any errors raised in the remainder of the routine. The system object Err is checked to see if an error was raised. If an error is raised the user is asked to select a file name.

 See the VBA Help for more information, eg "On Error statement". Many VBA statements will also raise an error, eg the Open statement.

 Private Sub GetMillTool(Name As String) ' Name of tool, eg "Flat - 10mm", no folder or extension

 ' Enable error handling 

 On Error Resume Next 

 ' Try to select given tool 

 App.SelectTool App.LicomdatPath & "LICOMDAT\MTOOLS.ALP\" & Name & ".AMT" 

 If Err.Number <> 0 Then 

 ' Failed so ask user 

 Err.Clear 

 Dim F1 As String, F2 As String 

 If Not App.GetAlphaCamFileName(Name & " not found: Select Tool", acamFileTypeTOOL, acamFileActionOPEN, F1, F2) Then 

 End 

 End If 

 ' Select chosen tool 

 App.SelectTool F1 

 End If 

 End Sub

PLIK: Example3_Facingarectangle

Example 3, Facing a rectangle
 
 

 Example 3, Facing a rectangle

 Shows how the 3D methods can be used to give control over the rapids between paths. If 2D methods were used the tool would rapid up to the safe rapid level between each pass.

 Public Sub TestManualToolPathFace()

 Const RapidLevel As Double = 25 

 Const ZDepth As Double = -2 

 Const X1 As Double = 0 

 Const Y1 As Double = 0 

 Const X2 As Double = 100 

 Const Y2 As Double = 75 

 Dim X As Double, Y As Double 

 Dim XMargin As Double, YStep As Double 

 Dim Direction As Boolean, First As Boolean 

  

 App.New 

  

 Dim Drw As Drawing 

 Set Drw = App.ActiveDrawing 

  

 Drw.CreateRectangle X1, Y1, X2, Y2 

  

 Dim Tool As MillTool 

 Set Tool = App.SelectTool(App.LicomdatPath & "LICOMDAT\MTOOLS.ALP\Flat - 20mm.amt") 

 XMargin = Tool.Diameter * 0.6 

 YStep = Tool.Diameter * 0.8 

  

 Dim MD As MillData 

 Set MD = App.CreateMillData 

 MD.SafeRapidLevel = RapidLevel 

 MD.RapidDownTo = ZDepth 

 MD.FinalDepth = ZDepth 

 MD.Attribute("LicomUKDMBOperationName") = "FACING" 

  

 Dim MTP As MillManualToolPath 

 Set MTP = MD.ManualToolPath(X1, Y1, ZDepth) 

  

 First = True 

 Direction = True 

 For Y = Y1 To Y2 + YStep * 0.5 Step YStep 

 If Direction Then 

 If Not First Then 

 MTP.Add3DRapid X1 - XMargin, Y, ZDepth 

 End If 

 MTP.Add3DLine X2 + XMargin, Y, ZDepth 

 Else 

 If Not First Then 

 MTP.Add3DRapid X2 + XMargin, Y, ZDepth 

 End If 

 MTP.Add3DLine X1 - XMargin, Y, ZDepth 

 End If 

 First = False 

 Direction = Not Direction 

 Next Y 

  

 Dim PS As Paths 

 Set PS = MTP.Finish 

  

 Drw.Options.ShowRapids = True 

 Drw.ThreeDViews = True 

  

 ' MsgBox PS.Count & IIf(PS.Count > 1, " Paths", " Path")

 End Sub

PLIK: Introduction2

Introduction - Introduction

Introduction

The Alphacam API is a COM programming interface to Alphacam. 
 The API contains many functions that can be called from Visual Basic for 
 Applications (VBA) in Alphacam. The functions can also be called by VBA 
 (in Excel, Access, Word etc) or by programs or DLLs created with Visual 
 Basic, Delphi, C++ or any other language that supports COM.

The API functions provide the programmer with direct 
 access to Alphacam functionality such as creating geometries, machining 
 them, controlling the input and saving of files etc. To run a VBA macro, 
 select UTILS | VBA Macros | Macros 
 if it is in a loaded project. If it is not loaded, use UTILS 
 | VBA Macros | Open VBA Project first.

The API interface uses an object 
 oriented approach. All of the functions described in this document 
 are methods or properties 
 which apply to an object. Thus, there is an 
 assumption that these methods will apply to the current state. For example, 
 there is a method RoughFinish 
 with no arguments. Instead of passing the geometries to be machined, the 
 RoughFinish method will act on the currently selected geometries.

The Alphacam API 
 (Application Programming Interface) is implemented for all levels ie Basic, 
 Standard and Advanced. However, only Advanced modules can create or edit 
 VBA macros. Standard and Basic modules can run VBA macros created in the 
 equivalent Advanced module. All modules can load DLLs or be run by external 
 programs.

Note that all Advanced modules include the ability to 
 run externally created Parametric Macros. The API does not replace Parametric 
 Macros, but is an additional, more powerful, way of controlling the functions 
 in an Alphacam module.

This document gives an overview of using the API, and 
 documents the objects, methods and properties available. The best way 
 to learn how to use the API is to look at the examples in the API directory 
 on the Alphacam cdrom. There are examples of VBA projects, and the complete 
 source for DLLs and EXEs in Visual C++ and Delphi.

Note that the Object 
 Browser in the View menu 
 of the VBA Editor contains a complete searchable list of all the objects, 
 methods and properties available in the program. It is the most accurate 
 description because it is automatically created at the same time as the 
 program. If a function is added between releases the help file may not 
 be updated, but the Object Browser will. Use it, even if you are not using 
 VBA. If you are using C++ or Delphi, make sure that you import the Type 
 Library which is bound into each Alphacam executable.

For support email: apisupport@licom.com

PLIK: Methods
================================================================================

Methods
 
 

 Methods

 AlphaCAM API objects have Methods. Methods are functions that may be called to perform tasks in AlphaCAM. For example, the MillData object has a RoughFinish method which is equivalent to the Rough / Finish command in the Machine menu in Mill AlphaCAM.

 AlphaCAM API objects support a Dual interface. To call a method use the syntax

  ObjectVariable.method (arguments)

 For example, the following examples show how to call the method OpenDrawing in the Application object in different languages. OpenDrawing has one argument (Name, the file name, a string) which is passed to the function. A Drawing pointer representing the drawing is returned. 

 acam is an object variable representing the Application object declared in the appropriate way for each language.

 Note that the full path is required for file names.

 VBA / VB

  Set drw = acam.OpenDrawing("C:\Licomdir\MyFolder\Example2.amd")

 OR

  acam.OpenDrawing "C:\Licomdir\MyFolder\Example2.amd" 

 For VBA / VB, the parentheses () must be used if the return value will be used. They must NOT be used if the return value is not used or the method does not return a value.

 C++ (Using Smart Pointers)

  acam->OpenDrawing("C:\\Licomdir\\MyFolder\\Example2.amd");

 Note ->, double-quotes, \\, and semi-colon at end.

 Delphi

  acam.OpenDrawing('C:\Licomdir\MyFolder\Example2.amd');

 Note single-quotes, and semi-colon at end.

 The only difference in the syntax of the three examples is in the rules of the language, therefore, in this help file, only the Basic versions of functions will be shown. C++ and other programmers should modify the syntax to suit as indicated above.

Example 1: 3D Solid Roughing using the Machining Engine

Const ATTR_GEO_Z_LEVEL_TOP As String = "LicomUKDMBGeoZLevelTop"

Const ATTR_GEO_Z_LEVEL_BOTTOM As String = "LicomUKDMBGeoZLevelBottom"

' 3D Solid Roughing using the Machining Engine.

' This macro drills some holes so the Pre-Drilled-Holes 
 option can be used,

' then roughs with a 10mm tool and then rest-roughing with 
 a 2mm tool

' If the OpenExternalFile call fails edit the path to the 
 Cadfiles folder on your PC.

Public Sub ZContourRoughingSolid()

    ' 
 Part

    App.OpenExternalFile 
 App.LicomdirPath & "licomdir\cadfiles\SIMPLE MILL PART.SLDPRT", 
 "", True

    

    ' 
 Material

    Dim 
 PMat As Path

    Set 
 PMat = App.ActiveDrawing.CreateRectangle(-85, -55, 85, 55)

    PMat.SetMaterial 
 25, 0

    

    ' 
 Create and drill holes that can be used to plunge into.

    ' 
 The Z value should be the bottom of the hole.

    MakeDrillHoles

    

    ' 
 Tool

    App.SelectTool 
 App.LicomdatPath & "licomdat\mtools.alp\flat - 10mm.amt"

    Dim 
 MD As MillData

    Set 
 MD = App.CreateMillData

    

    ' 
 Solids to machine

    SelectSolidsNotMat

    MD.SurfaceMCAction 
 = acamSurfaceMCActionROUGHING

    MD.PocketType 
 = acamPocketCONTOUR

    

    MD.SafeRapidLevel 
 = 30

    MD.MaxDepthPerCut 
 = 5

    MD.RapidDownTo 
 = 26

    MD.WidthOfCut 
 = 5

    MD.StockXY 
 = 0.5

    MD.StockZ 
 = 0.25

    

    MD.SurfaceMCZOrder 
 = acamSurfaceMCZOrderZONE

    MD.SurfaceMCUseFlatAreas 
 = True

  

    ' 
 Use V9 Machining Engine

    Dim 
 MDME As MillDataMachiningEngine

    Set 
 MDME = MD.MillDataMachiningEngine

    

    MDME.MillType 
 = AcamMillTypeClimb

    

    MDME.ApproachType 
 = acamMEApproachPreDrilledHoles

    MDME.FeedWhenPlunging 
 = True

       

    ' 
 Store the hole coordinates

    MDME.StartDrillPoints

    Dim 
 P As Path

    For 
 Each P In App.ActiveDrawing.Geometries

        If 
 P.PathType = acamPathGEOMETRY Then

            Dim 
 CP As CircleProperties

            Set 
 CP = P.GetCircleProperties

            If 
 Not CP Is Nothing Then

                MDME.AddDrillPoint 
 CP.CenterXG, CP.CenterYG, P.Attribute(ATTR_GEO_Z_LEVEL_BOTTOM)

            End 
 If

        End 
 If

    Next 
 P

       

    MDME.MachineSolid

       

    ' 
 Second tool

    App.SelectTool 
 App.LicomdatPath & "licomdat\mtools.alp\flat - 2mm.amt"

    

    SelectSolidsNotMat

    MD.SurfaceMCRoughingUsePreviousMachining 
 = True

    MD.MaxDepthPerCut 
 = 2

    MD.WidthOfCut 
 = 1

    MDME.ApproachType 
 = acamMEApproachHelix

    MDME.RampAngle 
 = 20

    MDME.MinimumRadius 
 = 1

    MDME.HighSpeedCornering 
 = True

    

    MDME.MachineSolid

End Sub

PLIK: Operations_Renumber

Operations.Renumber
 
 

 Operations.Renumber

 Renumber an operation.

 Syntax

 ops.Renumber (OperationNumber, NewNumber, Action)

 Long OperationNumber Number of op to renumber

 Long NewNumber  New number for this operation

 AcamOpRenumberAction

  Action   What to do if operation already exists.

 Remarks

 If an operation already exists with number NewNumber, the Action parameter determines what happens. It is either: acamOpADD_TO_OPERATION which means add the paths for op OperationNumber on to the end of paths for op NewNumber (if the tools are the same), or acamOpINSERT_IN_FRONT which means insert op OperationNumber in front of op NewNumber. The Operations object is invalid after using this method once. It must be recreated as in the example below.

 Example

 Renumber operations with the same tool. The Operations object is invalid after each renumber method call, so the function ReNumberOneOp is used. When it renumbers an operation it returns, destroying the object. It is then recreated in the Do While Loop.The loop is repeated until no more could be renumbered.

 Public Sub ReNumber()

 Dim Drw As Drawing 

 Set Drw = App.ActiveDrawing 

  

 Do While ReNumberOneOp(Drw.Operations) ' recreate Operations 

 Loop 

 End Sub

 ' Helper function for ReNumber

 Private Function ReNumberOneOp(Ops As Operations) As Boolean

 Dim I As Integer, J As Integer 

 For I = 1 To Ops.Count 

 For J = I + 1 To Ops.Count 

 If Ops(I).tool.Number = Ops(J).tool.Number Then 

 ' MsgBox "Trying to renumber " & I & " and " & J

 Ops.ReNumber J, I, acamOpADD_TO_OPERATION 

 ReNumberOneOp = True 

 Exit Function 

 End If 

 Next J 

 Next I 

 ReNumberOneOp = False 

 End Function

PLIK: Operations_StartResquence

Operations.StartResequence
 
 

Operations.StartResequence

For Lathe only, start resequenceing the operations.

Syntax

ops.StartResequence

Remarks

For AlphaV7 Lathe uses a different method from the other modules to determine the order of operations. Each operation has a sequence number, operations are ordered in the order of the sequence numbers. This allows operations in different turrets to be done in any order unlike previous versions which ordered the operations by turret. Call StartResequence then set the NewSequenceNumber property of each operation, then call FinishResequence.

Example

Assuming that there are at least two operations in the current drawing, this example swaps the first two. They can be in any turret/station.

Public Sub SwapOps1And2()

 Dim Drw As Drawing 

 Set Drw = App.ActiveDrawing 

 Dim Ops As Operations

 Set Ops = Drw.Operations

 Ops.StartResequence

 Ops(1).NewSequenceNumber = 2

 Ops(2).NewSequenceNumber = 1

 Ops.FinishResequence

End Sub

Release Notes for AlphaCAM V7.5

Release Notes for AlphaCAM V7.5

 

The version number passed to InitAlphacamAddIn is frozen at 20070810. 
 Add-in DLLs and VBA projects should use the VersionInformation object 
 if they need to restrict the versions of Alphacam that they can run with. 
 First test that the Version is >= 20070810, then get the VersionInformation 
 object using the App.AlphacamVersion property. You can either restrict 
 the add-in to work with a particular version by testing the Major and 
 Minor properties, currently 7 and 5 for version 7.5 or test Major * 1000 
 + Minor * 100 >= 7500. Then if necessary test the build number, which 
 will always increment until the Major or Minor numbers change.

 

You can also get the version information for loaded DLLs eg:

    Dim 
 VerInfo As VersionInformation

    Set 
 VerInfo = App.FileVersion("feature.dll")

 

Because no path is specified this will get the information for the version 
 of feature.dll which is loaded by Alphacam. A path can be specified if 
 you want to get information about a DLL that is not loaded by Alphacam.

 

Dependencies

An add-in DLL can now specify that another add-in DLL must be loaded 
 before this one. For example, AcamNest.dll must be loaded before AdvNest.dll, 
 so AdvNest exports the following function:

 

ACAMAPIFUN(BSTR) GetDependencies()

{

AFX_MANAGE_STATE(AfxGetStaticModuleState());

CString str("AcamNest.dll");

return str.AllocSysString();

}

 

Alphacam will look in the registry for DLLs to load in the same way 
 as before, starting with: HKEY_LOCAL_MACHINE\SOFTWARE\LicomSystems\aroutaps\Applications7500 
 where "aroutaps" is replaced by the name of the equivalent pre-V7.5 
 executable. Note that on 64bit XP or Vista the 32bit node must be used, 
 either by running regedit and going to :

HKEY_LOCAL_MACHINE\SOFTWARE\Wow6432Node or by running: %systemroot%\syswow64\regedit 
 using the Start | Run box.

 

Interfaces

In AlphaV7, properties were added to the Drawing object to get the interface 
 for the Parametric, Solid and STL add-ins, as a safer alternative to using 
 New or CreateObject or CoCreateInstance. In AlphaV7.5 these properties 
 must be used, the old ways will not work. This ensures that the correct 
 version of the add-in is used, rather than the most recently-registered 
 one.

Running Alphacam from other programs

 

Alphacam can be run from other programs using COM as before, with one 
 difference: the level that is run will depend on the license available, 
 not the name specified in the CreateObject call.

 

For example, in VB6/VBA:

 

Dim Acam As AlphaCAMRouter.App

Set Acam = CreateObject("aroutaps.application")

 

will run the highest level of Router available, eg ar5axaps (5-axis 
 Router) if a license is available.

 

Dim Acam As New AlphaCAMRouter.App

 

is not recommended. (Can cause problems on 
 Windows Vista)

 

If a level lower than the license is required, 
 set the registry entry:

 

ProgramLevel

 

under the key:

 

HKEY_CURRENT_USER\Software\LicomSystems\Acam\COM

 

to a numeric (DWORD) value:

 

1 = Basic

2 = Standard

3 = Advanced

4 = Advanced 3D 3 Axis

5 = Advanced 3D 5 Axis

6 = AlphaViewPlus

 

Alphacam will set it to zero (use default 
 level) after reading it.

 

For example, from VB.Net:

Imports Microsoft.Win32

        Dim 
 Rk As RegistryKey

        Rk 
 = Registry.CurrentUser.CreateSubKey("SOFTWARE\LicomSystems\Acam\COM", 
 RegistryKeyPermissionCheck.ReadWriteSubTree)

        Rk.SetValue("ProgramLevel", 
 AlphaCAMRouter.AcamLevel.acamLevelPROUTAPS, RegistryValueKind.DWord)

 

See \ApiV7.5\VB.Net\RunAcam on the CD for an example program.

 

For a C++ example, see \ApiV7.5\VisualCPP\RunAcam on the CD

 

Calling from .Net

 

When calling Alphacam from .Net the Alphacam exe may be left in memory 
 due to the way the .Net Garbage Collector works.

To avoid this add the following when the Alphacam object (eg Acam) is 
 finished with:

 

        ' 
 The following 4 lines make .Net release the Alphacam object, otherwise 
 Alphacam stays in memory

        Acam 
 = Nothing

        System.GC.Collect()

        System.GC.WaitForPendingFinalizers()

        System.GC.Collect()

Release Notes for AlphaCAM 01
 
 

 Release Notes for AlphaCAM 01

 AlphaCAM 01 includes VBA 6.2, which gives more language features and other advantages.

 For AlphaCAM 01 several new objects have been added, and various new properties and methods. The main difference is the change to the way that text is handled in AlphaCAM. Text is now stored as a text object, not as geometry lines and arcs. Text in the drawing is represented as a Collection of Text objects, accessed by the Text property of the Drawing object. Each Text object contains a Lines property which is a Collection of TextLine objects, one for each line of text in the object. the Text object also contains many properties eg Font.

 Text may be created as before using Drawing.CreateText, which for compatibility still creates text as geometry and returns it as a Paths object. A new method, Drawing.CreateText2, creates text as text and returns a Text object. Similarly for CreateTextAlongPath and CreateTextAlongPath2.

 A new object, MachiningDefaults, has been added to give access to the settings set by the user in Configure.

 For Lathe modules, a new object, TurnProgrammingPoint, gives access to multiple programming points for Turning tools.

 More objects can now have Attributes (Drawing, Element, MillTool, WorkPlane).

 Frame.RegisterImportFunction allows an Add-In to inform AlphaCAM that it can import a type of file.

PLIK: ReleaseNotesforAlphaCAM99

Release Notes for AlphaCAM 99
 
 

 Release Notes for AlphaCAM 99

 Differences between the API in AlphaCAM 98 and AlphaCAM 99 are documented here.

 AlphaCAM 98 had the first version of the API, with the Enable Basic script interpreter. AlphaCAM 99 replaces Enable with Microsoft VBA (Visual Basic for Applications) which gives you a complete programming environment built-in to AlphaCAM Advanced modules. (Standard and Basic modules can run VBA Macros, but not create or edit them).

 Due to the extra features of VBA, some API functions have been modified. In particular, any method which returned a list of Path objects by returning the first Path object and the number of paths in a parameter, have been changed to return a Paths object, which is a Collection of Path objects. For example, Drawing.CreateText and Path.BreakWithCuttingGeos have changed. See Method Changes and Collections.

 Object variables should now be declared with the correct type. For example:

 Dim Drw As Object

 should be replaced with:

 Dim Drw As Drawing

 This will run faster and help you to write the code because when you type "Drw." a popup window will appear with the methods and properties for this object. Typing the first few letters of the required one and pressing space will complete it.

 VBA is more strict than Enable about the use of parentheses () in method calls, the following rule must be followed:

 For VBA, the parentheses () must be used if the return value will be used. They must NOT be used if the return value is not used or the method does not return a value.

 For example (where Drw is a Drawing object, Line is a Path object):

 ' Use return value, must have ()

 Set Line = Drw.Create2DLine(0, 0, 100, 0) ' OK

 Set Line = Drw.Create2DLine 0, 0, 100, 0 ' NOT OK

 ' Ignore return value, must not have ()

 Drw.Create2DLine 0, 0, 100, 0 ' OK

 Drw.Create2DLine(0, 0, 100, 0) ' NOT OK

 Events may now be handled by more than one VBA Project. The only rule is that the event routines must be in a VBA Module called Events. Any number of VBA Projects may be loaded at the same time, each may have an Events module. If there is more than one event handler for an event they will all be called. (Unless a non-zero return value is returned, if a return value is expected.) Any event that returned a file name eg BeforeOpenFile, may return 2 to cancel the command. See Events.

 There are three ways to load VBA Projects automatically. Loaded projects (except in SysMacro) will be shown in the Utils | Add-Ins dialog box, and may be turned on or off with a check-box. They do not have to be called AutoLoad, they can be any name, and there can be more than one.

 1) VBA Projects of the correct type (eg *.AMB for Mill) in the StartUp folder in VBMacros in the default Licomdir will be loaded automatically. . The name of the file will appear in the Add-Ins dialog box.

 2) VBA Projects of the correct type in StartUp in the Alpha01 folder. They will appear in the Add-Ins dialog box.

 3) VBA Projects of the correct type in SysMacro in the Alpha01 folder. They will NOT appear in the Add-Ins dialog box - they will always be loaded.

 4) DLLs are loaded using the registry (see the samples), so can be anywhere. They will also appear in the Add-Ins dialog box.

 VBA Projects can add menu items when loaded, and/or may contain macros which can be run using the Utils | VBA Macros | Macros command. For a macro to appear in the dialog box it must be a Public Sub with no parameters.

 For programmers using other languages, the Type Library is now embedded into each AlphaCAM executable.

 AlphaCAM functions may now return errors, which may be trapped using VBA error handling. See Errors.

 Functions have been added to the API to add Attributes to paths. See Attributes.

 Many new objects and functions have been added.

PLIK: SubOperation_SetMillData

SubOperation.SetMillData
 
 

 SubOperation.SetMillData

 Set the machining data for this sub-operation. The associated tool paths will be deleted and regenerated, using the associated geometries.

 Syntax

 SubOp.SetMillData (MD)

 MillData MD MillData object

 Remarks

 The MillData object MUST be one returned by SubOperation.GetMillData.

 Examples

 The following examples assume that the referenced drawing file is available.

 It is part of the standard release cdrom installed in English (UK).

 Example 1, Change stock for operation 1 and regenerate tool paths

 Public Sub EditOperation1()

 App.OpenDrawing App.LicomdirPath & "licomdir\Tutorial\Mill Simple Shape + tool paths.amd" 

 Dim Drw As Drawing 

 Set Drw = App.ActiveDrawing 

  

 Dim SubOp As SubOperation 

 Set SubOp = Drw.Operations(1).SubOperations(1) 

  

 Dim MD As MillData 

 Set MD = SubOp.GetMillData 

  

 MD.Stock = 2 

  

 SubOp.SetMillData MD 

 End Sub

 Example 2, Change operation 2 from Drilling to Pecking

 Public Sub EditOperation2()

 ' App.OpenDrawing App.LicomdirPath & "licomdir\Tutorial\Mill Simple Shape + tool paths.amd"

 Dim Drw As Drawing 

 Set Drw = App.ActiveDrawing 

  

 Dim SubOp As SubOperation 

 Set SubOp = Drw.Operations(2).SubOperations(1) 

  

 Dim MD As MillData 

 Set MD = SubOp.GetMillData 

  

 MD.DrillType = acamPECK 

 MD.PeckDistance = 1 

  

 SubOp.SetMillData MD 

 End Sub

 Example3, Change the geometry for operation 3 and regenerate the tool paths

 Public Sub EditOperation3()

 ' App.OpenDrawing App.LicomdirPath & "licomdir\Tutorial\Mill Simple Shape + tool paths.amd"

 Dim Drw As Drawing 

 Set Drw = App.ActiveDrawing 

  

 Dim SubOp As SubOperation 

 Set SubOp = Drw.Operations(3).SubOperations(1) 

  

 Dim P As Path 

 Set P = SubOp.Geometries(1) 

 P.ScaleL 1.5, P.Elements(1).CenterXL, P.Elements(1).CenterYL 

  

 ' To regenerate the tool paths after the geometries are changed 

 ' just get and set the MillData object

 Set MD = SubOp.GetMillData 

 SubOp.SetMillData MD

Surface.Evaluate

Surface.Evaluate

Evaluate the surface at the given point. The coordinates 
 will be returned, and, optionally, the normal and derivative values.

Syntax

surface.Evaluate (S, T, Flags)

double S S parameter value

double T T parameter value

[Return] Variant  Returned array of doubles,

Remarks

If Flags is acamEvaluateCOORDS the returned array will 
 contain the X, Y and Z coordinates. For example, the following code will 
 display the XYZ coordinates at the point on the surface where the parameter

 from another CAD system):

 Dim V

 V = surface.Evaluate (.5, .5, acamEvaluateCOORDS)

 MsgBox "X=" & V(0) & ", 
 Y=" & V(1) & ", Z=" & V(2)

If Flags is acamEvaluateCOORDS_AND_NORMAL, the XYZ components 
 of the unit normal will also be returned, in V(3), V(4) and V(5)

See example Surface Example

 V(6) dx/ds

PLIK: SurfaceExample
================================================================================

Surface Example
 
 

 Surface Example

 The following routine draws a "Porcupine Map", that is, 3D polylines along the surface normal at points on the surface.

 Note:

 MinS, MaxS, MinT and MaxT are used to find the range for the parametric variables S and T. Surfaces created in AlphaCAM use the range 0 to 1, but surfaces imported from other systems can use any range.

 IsPointTrimmed is used to suppress drawing where the surface is trimmed.

 Public Sub SurfaceNormalVectors()

 Dim Drw As Drawing 

 Dim SF As Surface 

 Set Drw = App.ActiveDrawing 

 Set SF = Drw.UserSelectOneSurface("Pick a Surface") 

 Dim S As Double, T As Double, L As Double 

 L = 5 

 Dim V 

 For S = SF.MinS To SF.MaxS Step 0.05 

 For T = SF.MinT To SF.MaxT Step 0.05 

 If Not SF.IsPointTrimmed(S, T) Then 

 V = SF.Evaluate(S, T, acamEvaluateCOORDS_AND_NORMAL) 

 Dim P As PolyLine 

 Set P = Drw.Create3DPolyline(V(0), V(1), V(2)) 

 P.AddLine V(0) + V(3) * L, V(1) + V(4) * L, V(2) + V(5) * L 

 P.Finish 

 End If 

 Next T 

 Next S 

 End Sub

PLIK: SurfaceFacets
================================================================================

Surface Facets
 
 

 Surface Facets

 The facets for the surface can be accessed using the properties FacetsForShading or FacetsForMachining. The facets for shading are usually created using a larger tolerance than those for machining. The tolerance used for the machining facets is the property McFacetsTolerance.

 The facets can be read by storing the property in a Variant, and then accessing it as an array of doubles. The VBA function UBound gives the size of the array. The lower bound is zero. Each facet is given as 9 numbers, that is, XYZ for 3 points: X1, Y1, Z1, X2, Y2, Z2, X3, Y3, Z3.

 The example extracts the facets and draws them as 3D polylines.

 Public Sub CopyFacetsToPolylines(V As Variant) ' array of doubles

 Dim I As Long, N As Long 

 N = UBound(V) 

 For I = 0 To N Step 9 

 Dim P As PolyLine 

 Set P = App.ActiveDrawing.Create3DPolyline(V(I), V(I + 1), V(I + 2)) 

 P.AddLine V(I + 3), V(I + 4), V(I + 5) 

 P.AddLine V(I + 6), V(I + 7), V(I + 8) 

 P.AddLine V(I), V(I + 1), V(I + 2) 

 P.Finish 

 Next I 

 End Sub

 Public Sub MachineFacetsToPolyline()

 Dim Drw As Drawing 

 Dim SF As Surface 

 Set Drw = App.ActiveDrawing 

 Set SF = Drw.UserSelectOneSurface("Pick a Surface") 

 CopyFacetsToPolylines SF.FacetsForMachining 

 End Sub

 The facets can be set by creating an array in the same format and assigning it to the property.

Text Object

Public Sub SearchForString(SearchStr As String)

Dim T As Text 

For Each T In App.ActiveDrawing.Text 

Dim L As TextLine 

For Each L In T.Lines 

Dim S As String 

S = L.Text 

If StrComp(S, SearchStr) = 
 0 Then 

T.Selected = True 

T.Redraw 

MsgBox S 

T.Selected = False 

T.Redraw 

End If 

Next L 

Next T 

End Sub

 array Tmat(I), I = 0 to 11 gives the transformation matrix from local 
 to global coordinates.

XGlobal = wp.Tmat(0) * X + wp.Tmat(1) * Y + wp.Tmat(2) 
 * Z + wp.Tmat(3)

YGlobal = wp.Tmat(4) * X + wp.Tmat(5) * Y + wp.Tmat(6) 
 * Z + wp.Tmat(7)

ZGlobal = wp.Tmat(8) * X + wp.Tmat(9) * Y + wp.Tmat(10) 
 * Z + wp.Tmat(11)

Replace Tmat with Imat to transform from global to local.

Use Drawing.CreateWorkPlane 
 to create a new work plane or to find an existing one.

Use Drawing.WorkPlanes to get the work planes as a Collection.
